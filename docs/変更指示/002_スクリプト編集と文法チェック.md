## 0. 作業ルール

- 実装後は、変更したファイルだけをコミットし、`git pull --rebase origin main` のあと `git push origin main` まで行う。コミットメッセージは「変更指示002: スクリプトの編集・書き戻しと文法チェック」。
- 本書は `docs/CLAUDE_CODE_指示書.md` の「スクリプトは閲覧のみ」「書き込み対象は MI_ACTION_GROUP_POINT のみ」を上書きする。**書き込み対象に `SCRIPT` テーブルを追加する。ただし更新するのは本書 3.2 に書いた列だけとする。**
- `tools/check_compile.py` は検証済みの試作である。3章の文法チェックは、この試作のロジック（ラッパーの生成、csc の呼び出し、診断の解析）をそのまま移植すること。試作ファイル自体は変更・削除しない。

## 1. 目的

スクリプトタブを読み取り専用から編集可能にし、編集したソースをDBへ書き戻せるようにする。保存前に C# コンパイラで文法チェックを行い、誤りのあるソースが MI に渡らないようにする。

## 2. 実環境で確認済みの事実（この前提で実装する）

テスト環境（TESTDB01）で実際に書き換えて確認した。

| 項目 | 確認結果 |
|---|---|
| `SCRIPT.Script` の `<Source>` だけを書き換え、`<ScriptId>` を元のままにする | MI は新しいソースを実行する |
| 反映方法 | Apriso 標準の設定画面で「マシーンの更新」を押すと反映される。MI の再起動は不要 |
| MI 再起動後 | 新しいソースのまま |
| 標準画面との併用 | 直接書き換えた内容が正しく表示され、標準画面での「確認」と保存も通る |
| 標準画面の保存 | 同じ `SCRIPT.ID` の行を上書きし、`RowVersionStamp` を 1 増やす |
| `<ScriptId>` | ソースと入力変数（名前・型・順序）から決まる値。計算式は不明。**アプリは `<ScriptId>` を一切変更しない** |
| 改行 | DB上には LF のスクリプトと CRLF のスクリプトが混在する（標準画面で保存すると CRLF になる） |
| XML 内のエスケープ | `<Source>` 内では `&` `<` `>` が `&amp;` `&lt;` `&gt;` になっている。`"` と `'` はエスケープされていない |

## 3. 仕様

### 3.1 編集（gui/code_viewer.py、gui/script_tab.py）

- 編集できるのは `<Source>`（C# ソース）のみ。入力変数、呼び出しオペレーション、using などは編集対象にしない。
- 既存の「編集モード」が ON のときだけ、メインウィンドウのスクリプトタブのビューアを編集可能にする。OFF のときは従来どおり読み取り専用。別ウィンドウ（ScriptWindow）は常に読み取り専用のままとする。
- 編集機能: 元に戻す / やり直し（Ctrl+Z / Ctrl+Y）、タブ文字はタブのまま入力、複数行選択での Tab / Shift+Tab によるインデント増減、Enter 時に前行のインデントを引き継ぐ。
- 未保存の変更があるときは、見出しのタイトル末尾に「●」を付け、既存のツールバーの「保存」「元に戻す」を有効にする。「元に戻す」はDBから読み込んだ内容に戻す。
- 未保存のままアクションを切り替える、再読込する、編集モードを OFF にする、アプリを終了する場合は確認する（ポイントタブの既存の確認と同じ扱い）。
- エディタ内部では改行を `\n` に統一して扱う。読み込み時に元の改行方式（ソースに `\r\n` が含まれていれば CRLF、なければ LF）を記録しておき、書き戻すときにその方式へ戻す。

### 3.2 書き戻し（core/script_parser.py、core/change_executor.py）

**新しい XML の組み立て**

- 元の `SCRIPT.Script` の文字列のうち、最初の `<Source>` と最初の `</Source>` に挟まれた部分**だけ**を、新しいソースをエスケープした文字列で置き換える。それ以外の部分は1文字も変えない。
- XML パーサで読み込んで出力し直す方法は使わない（属性の順序、名前空間宣言、改行、`<ScriptId>` などが変わるおそれがあるため）。
- エスケープは `&` → `&amp;`、`<` → `&lt;`、`>` → `&gt;` の3つだけを、この順で行う。
- 元の XML に `<Source>…</Source>` が見つからない場合、または `<Source />` の形だった場合は、書き戻しを行わずエラーにする。
- 組み立てた XML を `parse_script()` で読み直し、取り出したソースが編集後のソースと一致すること、入力変数と呼び出しオペレーションが元と変わっていないことを確認する。一致しなければ保存を中止する。

**更新 SQL**（パラメータ化クエリ）

```sql
UPDATE SCRIPT
SET Script          = ?,
    LastUpdateOn    = GETUTCDATE(),
    LastUpdatedBy   = ?,
    RowVersionStamp = ISNULL(RowVersionStamp, 0) + 1
WHERE ID = ? AND RowVersionStamp = ?;
```

- 影響行数が 1 でなければ「他で更新された」としてロールバックする。
- `MI_ACTION` の `ValidationResult` / `ValidatedOn` / `ValidatedBy` など、`SCRIPT` 以外のテーブルは更新しない。
- 既存の書き込み手順（`docs/CLAUDE_CODE_指示書.md` の 5.10）をそのまま適用する: 編集モード、プレビュー、実行前の退避（更新前の行の全列を JSON、元に戻すための SQL を `.sql`）、1トランザクションでの実行、ログ出力、実行後の再読込。
- 退避する `.sql` は、`Script` を元の文字列に戻す UPDATE 文とする。文字列リテラルは `N'…'` とし、`'` は `''` にエスケープする。

**プレビュー**

- 保存を押すと、まず 3.3 の文法チェックを実行する。その後、プレビューダイアログに次を表示する。
  - 接続先（サーバー / データベース名）を目立つ位置に表示する
  - 対象（グループ名 / アクション名 / SCRIPT.ID）
  - 変更前と変更後のソースの差分（既存の差分表示を使う）
  - 文法チェックの結果（OK、エラー件数、またはチェック未実施の理由）

**保存後**

- 「保存しました。MI へ反映するには、Apriso のマシーンインテグレータ設定で『マシーンの更新』を実行してください。」と表示する。アプリから MI の更新は行わない。

### 3.3 文法チェック（core/compile_checker.py を新規作成）

`tools/check_compile.py` の次の部分を移植する: `find_compilers`、`parse_parts`、`_cs_type`、`build_wrapper`、`compile_check`、診断の正規表現。

- **コンパイラの選択**: 設定 `compiler.csc_path` が空でなければそれを使う。空の場合は検出した中の先頭（Visual Studio 付属の Roslyn を優先し、なければ `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`）を使う。
- **ラッパー**: 入力変数は XML の型どおりのフィールド（`System.` で始まらない型は `dynamic`）、`MI` と `Log` は `dynamic`、`ExecuteOperationSync_<名前>` は XML の Inputs / Outputs から生成する（`in<Key>` は既定値付き、`out<Key>` は `out` 引数、ほかに `employeeNo`）。ソースの直前に `#line 1 "script"` を置き、エラーの行番号をスクリプトの行番号に一致させる。
- **入力変数とオペレーションの定義は、DBから読み込んだ元の XML のものを使い、ソースだけを編集中の内容に差し替えてチェックする。**
- **実行**: ワーカースレッドで実行する。一時フォルダにラッパーを書き出して csc を呼び、出力 DLL は捨てる。タイムアウトは 60 秒。コンソールウィンドウが出ないようにする（`subprocess` の `creationflags=CREATE_NO_WINDOW`）。
- **結果**: 診断（種別、コード、行、桁、メッセージ、スクリプト内かラッパー内か）のリストを返す。ラッパー側で起きたエラーは「定義の生成に起因するエラー」として、スクリプトのエラーと区別して返す。

**画面**

- スクリプトタブの見出しバーに「文法チェック」ボタンを追加する（ショートカット F7）。編集モードでなくても実行できる。
- ビューアの下に、折りたたみ可能な「エラー一覧」パネルを追加する。列は `種別、行、桁、コード、メッセージ`。行をダブルクリックすると該当行へ移動する。エラーのある行は、ビューアの行番号エリアに印を付け、行の背景をエラー色にする（色は `gui/styles.py` に定義）。
- チェック結果は見出しバーに「文法チェック: OK」「文法チェック: エラー 3 件」のように表示する。ソースを編集したら「未チェック」に戻す。
- **保存時の扱い**:
  - エラーが 1 件以上ある場合は保存させない（エラー一覧を表示して中止）。
  - コンパイラが見つからない、またはタイムアウトなどでチェックできなかった場合は、その理由を示したうえで「チェックなしで保存しますか」と確認し、明示的に承認されたときだけ保存に進む。
- パネルの下部に、次の注意書きを常時表示する: 「このチェックは Apriso 本体のコンパイルと同一ではありません。MI・Log のメソッド名や引数は検査されません。」

### 3.4 設定（core/config_manager.py、gui/connection_dialog.py は変更しない）

`config.json` に次を追加する。

| キー | 型 | 既定値 | 内容 |
|---|---|---|---|
| `compiler.csc_path` | str | `""` | 使用する csc.exe のパス。空なら自動検出 |
| `compiler.timeout_seconds` | int | `60` | コンパイルのタイムアウト |

設定画面は追加しない（必要な場合は `config.json` を直接編集する）。メニュー「ヘルプ → バージョン情報」に、検出されたコンパイラのパスを表示する。
